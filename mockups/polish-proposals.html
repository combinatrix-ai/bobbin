Five polish proposals

The places where the popover still reads as unfinished, drawn at its real 392pt width. P1 folds in the two open mockups (settings-placement, footer-usage); P2–P5 are new. The hover-dependent mocks are live — move the pointer over them.

  • Popover 392×560
  • P2 and P4 are pure additions, no layout change
  • P1 decides the two pending mockups
P1

Landing chrome: settle the gear row

The open question from settings-placement.html. Two coherent directions survive: (a) the folder moves out of the composer onto the 24pt line, so the landing view and the conversation share one meta-line grammar — folder left, controls right. (b) the row disappears and a 28pt footer takes gear + power + the usage meter from footer-usage.html variant 3.

Recommend (a) — no new chrome, and the two views finally rhyme. Pick (b) only if the usage meter is wanted now.
P2

Thread rows: hover feedback, quieter stars, and a way to delete

Today every row shows a hollow star at all times — six outlined stars of noise for an action used once per thread — and rows give no hover feedback, so the list feels inert. Worse, there is no way to delete a thread; the only exit is waiting seven days. Proposed: rows highlight on hover, the star appears on hover only (saved rows keep the filled star as their badge), and right-click opens a small menu with Save and keep / Delete now. Delete needs no confirm — the whole product premise is that threads are disposable.

Pure addition · fixes a real gap (delete) while removing noise
P3

Conversation controls: make the menus feel clickable

“Auto review · luna · xhigh” and the folder are all menus/buttons, but they render as 9.5px tertiary mono text — identical to the read-only metadata style the README screenshots use. Nothing invites a click, so the app’s best feature (per-thread tuning) hides in plain sight. Proposed: the resting look stays exactly as quiet, but on hover each item gets the standard chip background and a small chevron. No layout shift — the chip paints inside the existing 24pt line.

Zero cost at rest · discoverability only appears under the pointer
P4

Transcript: edit/regenerate icons rest at zero

The pencil under every user bubble and the redo arrow under every reply currently idle at 48% opacity — the transcript carries a faint grey barnacle per message. Proposed: rest at 0, fade in on bubble hover (keyboard focus still reveals them, so accessibility is unchanged). The transcript becomes pure conversation until the pointer asks for tools.

One-line change · opacity 0.48 → 0 at rest
P5

Small consistencies

Three one-liners that only show up as “something feels off”:

  • Saved rows lose their timestamp. Metadata is hidden the moment a thread is saved, so the Saved section is the only place with a bare right edge. Show the same “3d ago” — the star already marks the state. (Drawn in P2’s proposed list.)
  • Selected-row tint only exists in the Saved section. isSelected is hard-coded false for active threads, true only for saved ones — so returning from a conversation highlights a saved row but never an active one. Either pass the real selection for both or drop it for both; today it reads as a rendering glitch.
  • The two composers disagree about the folder. Landing keeps it inside the card, the conversation keeps it on the meta line. P1(a) resolves this for free; if P1(b) wins, move the conversation’s folder into its composer instead so there is still one grammar.
